# ADR 0001: 开盘啦做发现，雪球做内容

## 状态

已接受

## 背景

News Harness V1 的内容来源是雪球"热门"和"达人"两个泛流量流。这个策略有两个问题：

1. 泛热门里大量是权重股、老登股的日常讨论，与短线题材热点无关。
2. 每次抓到的内容高度重复，缺乏"今天市场在炒什么"的针对性。

用户希望系统每天产出的内容跟着当日题材走，而不是跟着雪球平台推荐算法走。同时用户已有一个独立的"花椒短线"项目，里面维护了 130 个 A 股数据接口的完整合同（其中开盘啦 46 个 P0），涵盖板块强度、竞价异动、涨停原因、连板梯队等题材信号。

## 决策

把内容发现拆成两个独立阶段，用不同数据源：

1. **发现阶段**：调用开盘啦接口，获取当日题材强度、竞价异动、涨停原因和连板梯队，生成每小时的 Target Stock 清单（最多 12 只）。
2. **采集阶段**：对 Target Stock 逐只调用雪球股票讨论接口，按时间排序获取最近帖子，应用固定评论数门槛（>= 10）后进入现有管线。

开盘啦只提供结构化市场信号，不提供文章内容。进入时间线和 MCP 的正文必须且只能来自雪球原始帖子。

## 为什么选这个方案

### 备选方案 A：继续用雪球热门流 + DeepSeek 题材过滤

否决理由：DeepSeek 无法弥补"根本没抓到相关帖子"的问题。如果热门流里没有 AI 算力的讨论，模型再聪明也筛不出来。这是信号源的问题，不是过滤的问题。

### 备选方案 B：直接用开盘啦的复盘文章做内容源

否决理由：开盘啦的文章是平台编辑内容，不是社区讨论。用户明确要求最终内容来自雪球（有真实评论互动），且开盘啦部分接口被标记为 excluded/partial，可靠性不够。

### 备选方案 C：用财联社电报 + 韭研公社做内容源

否决理由：财联社偏快讯不是讨论，韭研公社内容形态合适但需要额外建 connector，且用户已有雪球登录态和成熟抓取路径。先用开盘啦信号 + 雪球内容是最小改动路径。

## 后果

### 正面

- 内容每天自然不同：竞价异动板块天天变，连板梯队天天变。
- 雪球定向搜索比泛热门流命中率高得多。
- 开盘啦接口是结构化数据，不需要浏览器渲染。
- 现有管线（DeepSeek 预测、1h/4h 回看、MCP 导出）全部保留，改动集中在 source 层。

### 负面

- 新增开盘啦 API 调用，引入新的故障点（接口漂移、鉴权变化）。
- 某些小时可能没有任何股票的讨论帖子过评论门槛，产出为零。
- 需要维护两套数据源的连接器。

### 缓解

- 开盘啦接口有完整 schema 合同和验证 cases，漂移可检测。
- 零产出是显式状态（ok_no_candidates），不伪装成失败也不降低门槛。
- 两套 connector 各自独立测试，互不阻塞。
- KPL-46 的历史 request case 在 2026-08-23 live GET 中返回 `errcode=1020`，在重新验证参数前不启用；禁止用静态 PlateID 或猜测参数伪装题材成分股能力。
- KPL-79/80 只观察到交易时段外空数组，且上游文档明确缺少非空字段样本；在取得非空合同前不启用，也不把板块 ID 猜成股票代码。KPL-47 仅按本周期目标股票动态传入 `StockID`，禁止使用历史固定股票。
